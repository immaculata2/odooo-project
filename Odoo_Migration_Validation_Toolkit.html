1 — Purpose of the artefact

This document frames the migration of Labocast Kenya's Odoo Community v10 environment from provider Octaly's hosting to an independent infrastructure. It serves as the guiding thread to verify that the takeover is reliable, documented, and ready for production — before any final cut-over.

2 — Project context

Labocast Kenya runs an Odoo Community v10 database hosted and maintained by Octaly (labocast-kenya.octaly.app). As part of structuring the Reuni Dent / Labocast group's operations, management decided to take back full ownership of this environment.

  • 01/07/2026
    Discussions opened with a technical Odoo / DevOps consultant for the takeover and security hardening of the database.
  • 02–07/07/2026
    Mission scoping: audit, data recovery, redeployment, security hardening, backups, documentation.
  • 14/07/2026
    Octaly begins preparing the handover package (PostgreSQL dump, filestore, custom modules, dependencies).
  • 27/07/2026
    Octaly provides the link to the data and Labocast Kenya-specific modules.
  • 30/07/2026
    Full package forwarded to the technical consultant in charge of the takeover.

3 — Target architecture

Rebuilt on a clean infrastructure, independent from Octaly's internal architecture (not disclosed):

  • Dedicated or cloud Linux server (Ubuntu)
  • PostgreSQL — version compatible with Odoo Community v10
  • Python — environment and dependencies compatible with existing modules
  • Odoo Community v10 — database + filestore restoration, reinstallation of custom modules
  • Nginx front-end, with SSL certificate
  • Hardening: SSH key authentication, firewall (UFW), Fail2ban, root login disabled
  • Daily automated backups, with a restore test
